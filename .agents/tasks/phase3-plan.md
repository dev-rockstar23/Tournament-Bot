## Architecture Decisions

**State machine location:** A dedicated `packages/tournament-engine/src/state-machine.ts` holds all valid TOURNAMENT_TRANSITIONS and MATCH_TRANSITIONS as plain data, plus `assertTournamentTransition` and `assertMatchTransition` helpers that throw typed errors. API routes import these helpers — no state logic leaks into route files.

**Scoring engines are pure functions:** `packages/game-rules` exposes `calculateMatchScore`, `calculateStandings`, and `applyTiebreakers` per game. They receive plain objects and return plain objects. Zero Prisma calls inside them. The `packages/scoring` package owns `computeTournamentStandings` which calls Prisma, maps Decimal→Number, then feeds pure data into the engines.

**Atomic slot reservation:** The registration POST wraps `prisma.$transaction` with `prisma.$executeRaw('SELECT ... FOR UPDATE')` on the tournament row to prevent double-booking. `acceptedCount` is incremented inside the transaction. Waitlist path is taken when `acceptedCount >= teamCapacity`.

**OutboxEvent pattern:** Every state-mutating route appends an `OutboxEvent` row inside its transaction. The worker picks it up asynchronously. This is the only way async Discord notifications are scheduled.

**ScheduledJob for matches:** Each match bulk-create writes 4 `ScheduledJob` rows (REMINDER_24H, REMINDER_30M, ROOM_RELEASE, RESULT_DEADLINE) all inside the same transaction. Reschedule cancels old jobs and inserts new ones.

**Prisma Decimal→Number boundary:** Any route that returns `ScoreEvent.points` or `Award.entryPrice` must call `Number(event.points)` — never serialize Decimal objects to JSON.

**Admin pages follow the existing pattern:** Server component fetches data + auth check, passes serialized props to a `'use client'` component that handles filters and mutations. All admin routes are protected via `withPermission(AppRole.TOURNAMENT_MANAGER, ...)` or the layout's REFEREE guard.

**Public routes must never expose:** `RoomCredential`, PENDING registrations, PENDING_REVIEW result submissions, or any other internal-only fields.

## Key Rules (enforced in every item below)

1. **ALL DB queries include `guildId` scope** — every `prisma.*` call carries `where: { guildId }` or reaches guildId through a relation.
2. **Never expose** `room_credentials`, PENDING registrations, or PENDING_REVIEW submissions from public routes.
3. **Use camelCase Prisma field names** — `teamCapacity`, `registrationOpenAt`, `guildId`, not snake_case.
4. **State machine transitions enforced at API level** — call `assertTournamentTransition` / `assertMatchTransition` before any status update.
5. **Scoring engines are pure functions** — no DB calls inside `packages/game-rules`.
6. **Prisma Decimal → Number only at the edge** — `Number(decimal)` in route handlers/serializers, not inside packages.
7. **Do NOT modify** `d:\Discord Projects\Tournament-Bot\PLAN.md`.
